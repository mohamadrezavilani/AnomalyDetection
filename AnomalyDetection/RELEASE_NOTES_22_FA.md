## اصلاح

schema_setup ابتدا فقط catalog اشیای schema خود AD را می‌خواند. وجود جدول‌ها و ستون‌های لازم، نوع ستون، جدول مقصد شاخص و معتبر/آماده‌بودن شاخص بررسی می‌شوند. default صریح target_scope نیز کنترل می‌شود. در ساختار کامل، هیچ‌یک از۱۱۱دستور DDL دوباره اجرا نمی‌شود. اگر شاخص یا ستون افزایشی واقعاً کم باشد، فقط همان دستور لازم در transaction قبلی اجرا می‌شود. نصب تازه همچنان اشیای لازم را می‌سازد؛ markerها، migrationهای داده، قفل تک‌نویسنده و کنترل نسخه حذف نشده‌اند. نوع ناسازگار ستون یا شاخص نامعتبر به‌صورت روشن رد می‌شود؛ صرف وجود نام جدول، ساختار را معتبر اعلام نمی‌کند. این بررسی اعتبارسنجی تمام constraintهای ممکنِ یک schema دستکاری‌شده نیست.

Worker مراحل اتصال، گرفتن قفل نویسنده و آماده‌سازی schema را جدا ثبت می‌کند. خطای راه‌اندازی شامل مرحله، قدم schema و حداکثر۱۶شناسهٔ دستور/زمان/SQLSTATE است؛ متن SQL، پارامترها و credential ثبت نمی‌شوند.55P03 با وضعیت WAITING_FOR_DATABASE_LOCK مشخص می‌شود. timeout اتصال/قفل افزایش نیافته و هیچ session یا قفلِ فرایند دیگر لغو نشده است. اگر قفل روی یک migration ضروری یا خود اتصال باقی باشد، خطا پنهان نمی‌شود و گزارش تازه محل آن را دقیق‌تر نشان می‌دهد.

## آزمون و حد تأیید

۱۵۴آزمون واحد پاس شدند:۱۵۱قبلی و۳آزمون دستورهای schema. SQL/HTTP محصول و مجموعه‌های محتوا۱۹، جداسازی آمار۲۰، فهرست و نوبت‌های مستقل۲۱ و راه‌اندازی۲۲ با کد۲۲ دوباره اجرا شدند. SQL۲۲ نصب تازه، restart بدون DDL، حفظ داده/cursor، ترمیم فقط یک index یا ستون، خطای55P03 و retry موفق تا ثبت ارزیابی، تشخیص نوع ناسازگار و حفظ fixture منبع را می‌سنجد. خطای55P03 با SQL واقعی در DB fixture تزریق می‌شود؛ این آزمون قفل واقعی میان دو اتصال native نیست.

نصب/ارتقای استخراج‌شده نیز آزموده می‌شود. در validation، گزارش‌های تازه build22 دارند؛ گزارش‌های قبلی با برچسب اصلی خود شاهد تاریخی‌اند. محیط SQL ایزوله PostgreSQL18.6/WASM و نصب Linux است. native Windows/PostgreSQL22، هم‌زمانی دو اتصال، ظرفیت/تأخیر و precision/recall تولید اینجا NOT_RUN/NOT_MEASURED هستند. پذیرش مالی به شاهد تکمیلی Backend وابسته است. تا پیشرفت واقعی Worker و نتیجهٔ شاهددار سناریوها تأیید نشود، آمادگی قطعی ارائهٔ زنده اعلام نمی‌شود.
