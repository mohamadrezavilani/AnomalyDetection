# آزمون و پذیرش نسخهٔ ۲۱

۱۵۱ آزمون واحد با کد جاری اجرا شده‌اند. قرارداد SQL/HTTP محصول، لغو SQL و ادامهٔ پردازش۱۵، شاهد/نرخ/مدل ثانویه۱۸، محتوا و مسیر فنی۱۹، جداسازی آمار۲۰، فهرست واحد و نوبت‌های مستقل۲۱ و exporter روی همین کد دوباره اجرا شده‌اند. گزارش مستقل نصب/ارتقای بسته، داده و config قبلی را حفظ، استخراج تمیز را اجرا و hash اعضا را کنترل می‌کند. گزارش‌های واقعاً اجراشده build21 دارند؛ سایر گزارش‌ها شاهد تاریخی‌اند.

- تکرار همان قبض با تغییر trace/IP، تنوع موضوع، تغییر پاسخ موفق، مسیر اجرایی ناقص، چرخش IP و API فنی، نمونه‌های عادی و دادهٔ ناکافی آزمون‌های مستقل دارند.
- پروندهٔ پایدار، شواهد دیررس، CAS، ابطال ورودی تغییرکرده و عدم شمارش دوبارهٔ RequestID حفظ‌اند.
- timeout آمار، منبع، مدل قبلی، انتخاب شاهد یا نگهداری کمکی نباید بررسی پروفایل/سناریو را گرسنه نگه دارد. خطا با SQLSTATE57014 واقعی در پایگاه ایزوله تزریق شده است.
- نمونهٔ۳۲درخواست یک‌snapshot برای پاسخ/مسیر، census و حجم کامل نیست و هیچ actor/رفتار/صفر ساختگی ایجاد نمی‌کند.
- /incidents و آدرس قدیمی /scenarios یک فهرست دارند؛ HTML راست‌به‌چپ در تراکنش read-only بررسی شده است.

SQL fixture از PostgreSQL18.6/WASM استفاده می‌کند؛ این آزمون احراز هویت native، شبکه، COPY، هم‌زمانی چنداتصالی، دوام یا قفل Windows را تضمین نمی‌کند. native Windows/PostgreSQL21 و سنجش ظرفیت، تأخیر و precision/recall تولید و آزمون تصویری مرورگر انجام نشده‌اند. پذیرش مالی نیازمند شاهد مکمل Backend است.

پذیرش نصب واقعی با acceptance-report --seconds 60 و همان دادهٔ قبلی انجام می‌شود. گزارش باید هویت۲۱، پیشروی مسیرهای مستقل، نتیجهٔ سناریوها، شمار شاهد معتبر و جاری‌بودن تصمیم را نشان دهد. RUNNING/heartbeat به‌تنهایی قبولی نیست؛ INSUFFICIENT_DATA یا گزارش ناقص را موفقیت تشخیص حساب نکنید. تمام ۹ سناریوی واقعی هنوز از آزمون مصنوعی قابل تأیید نیستند. فرمان کامل در RELEASE_NOTES_21_FA.md آمده است.
